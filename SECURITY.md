# Security Policy

## Supported Versions

This project has no release history yet. Security fixes are applied to the latest commit on the default branch. No backporting is provided.

The default branch is `main`.

| Version                            | Supported          |
| ---------------------------------- | ------------------ |
| Latest commit on `main`            | :white_check_mark: |
| Any older commit or prior snapshot | :x:                |

## Reporting a Vulnerability

**Do not open a public issue for security vulnerabilities.** Public reports
expose users to risk before a fix is available.

GitHub private vulnerability reporting is not currently enabled for this
repository, so please report privately by contacting the following
maintainer directly on GitHub:

- f0xb17 (@f0xb17)

If private vulnerability reporting is enabled for this repository in the
future, use that route instead: open the **Security** tab and choose **Report a
vulnerability**.

## What to Include

To help us assess and fix the issue quickly, include:

- A description of the vulnerability.
- The affected component, file, or command.
- Steps to reproduce the issue.
- The potential impact, and who or what is affected.
- A proof of concept, if you have one.

## What to Expect

These are target timelines, not guarantees:

- We aim to acknowledge your report within **7 days**.
- Please allow **90 days** for a fix before any public disclosure.

Remediation time depends on the severity and complexity of the issue, so the
actual fix may take longer. We will keep you informed of progress and discuss
disclosure timing with you if more time is needed.

## Out of Scope

The following are out of scope for this policy:

- **Issues in third-party dependencies.** Report these to the upstream project
  that maintains the dependency. If a dependency vulnerability affects this
  project, still let us know so we can update or mitigate it.
- **Social engineering.** Attempts to manipulate maintainers or contributors
  into revealing information or taking unsafe actions.
- **Physical-access attacks.** Attacks that require physical access to a device,
  machine, or network.

Thank you for helping keep this project and its users safe.
